# Быстрый запуск

Комплект готов для изучения кода, демонстрации и последующего тестирования в AD-лаборатории. Живая Windows/AD-проверка ещё не выполнена.

## Демо без подключения к инфраструктуре

В папке проекта:

```powershell
./Invoke-RelayADHealth.ps1 -Mode Demo
```

Откройте напечатанный путь `report.html`. Код завершения 2 ожидаем: в синтетическом сценарии намеренно показаны предупреждения и ошибка DNS. Готовый пример находится в `demo/sample/report.html`. Все имена и адреса вымышлены.

## Живой запуск

Нужны Windows PowerShell 5.1 x64, установленные RSAT AD и Group Policy Management, согласованный домен и текущая Windows-учётная запись с разрешёнными правами чтения. PowerShell 7 для живого режима v0.1 намеренно не используется.

Скопируйте `config/community.json` в `config/customer.local.json`, замените Domain и Server. Запустите в согласованной среде после лабораторной проверки:

```powershell
.\Invoke-RelayADHealth.ps1 -Mode Live -ConfigPath .\config\customer.local.json -OutputRoot C:\RELAY-Private\Reports
```

Скрипт не запрашивает пароли, не устанавливает компоненты и не меняет AD, DNS, GPO или службы. Он создаёт отчётные файлы. Права на выходную папку задаются заранее вне инструмента. Живые отчёты и конфигурацию заказчика нельзя публиковать.

`Pass` подтверждает только конкретную проверку. `Info` требует интерпретации, `Warning` — внимания, `Error` — означает недоступные/неполные данные, `Skipped` — отключённую проверку. Общего заключения «AD полностью исправен» нет. SYSVOL проверяется на доступность, W32Time сохраняется для ручного анализа, привилегии — по прямому членству; ограничения подробно перечислены в README.

Тесты: `./tests/Run-Tests.ps1`. Публикация отдельного репозитория описана в `docs/PUBLISH-CODEBERG.md`; существующий сайт не изменён.
